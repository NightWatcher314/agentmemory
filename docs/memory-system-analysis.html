一眼看懂

agentmemory 的核心不是一个单表 memory，而是一组围绕 coding session 运转的状态集合。 hooks 把事件写成 observation；显式保存和自动归纳把 observation 提炼为 memory； 检索层把 BM25、向量和图关系融合；注入层再按预算把可用上下文拼回 agent。

输入面

  • src/hooks/*.ts 监听会话、提示词、工具调用、失败、停止、子任务等生命周期。
  • /agentmemory/observe 接收 hook payload 并转给 mem::observe。
  • memory_save 或 /agentmemory/remember 显式写长期记忆。
  • session/start 建 session，并可返回启动上下文。

处理层

  • mem::observe 做隐私清理、去重、图片抽取、session 计数和 raw stream。
  • 默认用 synthetic compression，不配置 LLM 也能得到可检索的 compressed observation。
  • mem::remember 对长期记忆做相似度 supersede、版本化、project/agent scope。
  • 索引层维护 BM25、可选 vector index、可选 graph retrieval。

输出面

  • mem::context 输出 <agentmemory-context> 包，用于注入。
  • memory_smart_search 返回 compact results，可再 expand。
  • viewer 通过 stream 和 REST 展示 sessions、observations、graph、health。
  • skills 给 agent 行为提示，MCP tools 给 agent 可调用能力。

采集链路

每次工具调用或用户提示并不是直接变成长久记忆。它先进入 observation 流，经过清洗和压缩， 变成可被搜索的事实片段。长期 memory 是第二阶段的产物，可以显式保存，也可以由 consolidation 归纳。

01 hook

Agent 事件

session start、prompt submit、post tool use、stop 等 hook 脚本读取 stdin JSON。

02 REST

HTTP 边界

hook 调用 /agentmemory/observe，API 层校验 sessionId、project、cwd、timestamp。

03 raw

RawObservation

mem::observe 脱敏、去重、抽取 toolName、prompt、图片引用，然后写 KV。

04 compressed

CompressedObservation

默认 synthetic；开启自动压缩时走 LLM。结果包含 title、facts、narrative、concepts、files。

05 indexed

可检索资产

写入 BM25；若有 embedding provider，也写 vector index；并通过 stream 推给 viewer。

关键点： observation 是“发生过什么”，memory 是“应该长期记住什么”。这两者在 KV 里分开存，但都会进入检索索引。

状态模型

状态不是一个数据库表，而是很多 KV scope。核心 scope 定义在 src/state/schema.ts。 其中 session 和 observation 是时间线，memory 和 lessons 是长期知识，index/graph/facets/actions 是增强层。

mem:sessions

会话元信息：project、cwd、startedAt、status、observationCount、agentId、firstPrompt。

mem:obs:{sessionId}

该 session 下的 raw 或 compressed observations。是回放、总结、检索的主要事实来源。

mem:memories

长期记忆：pattern、preference、architecture、bug、workflow、fact。支持版本和 supersede。

mem:summaries

session summary：标题、叙事、关键决策、修改文件、concepts。给 context 和 handoff 使用。

mem:index:bm25

关键词检索索引。启动时可从持久化快照加载，不完整时可后台重建。

mem:emb:{obsId}

embedding/vector 相关状态。维度不匹配时启动会拒绝加载或按配置丢弃旧索引。

mem:graph:*

实体节点、边、name index、edge key、degree、snapshot。用于图检索和关系展示。

mem:lessons / mem:slots

反思提炼出的 lessons 和可 pin 的 working memory slots，会进入上下文包。

检索与注入

这里有两条容易混淆的路径：search 是主动查询，context 是被动注入。 前者回答“我现在要找什么”；后者回答“新 session 或 compact 前应该带哪些背景”。

主动查询：memory_smart_search

MCP tool 进入 mem::smart-search。 它调用 HybridSearch：BM25 搜关键词，vector 搜语义，graph 用实体关系扩展，再按 combined score 返回 compact result。 需要全文时可用 expandIds 展开 observation。

被动注入：mem::context

由 session/start、pre-compact 或手动 REST 调用。 它收集 pinned slots、project profile、lessons、最近 session summaries、重要 observations， 按 recency 和 token budget 拼成 XML 包。

几类“记忆”

代码里“记忆”至少有五种形态。维护时最怕把它们混为一谈，例如把 observation 当成长期 memory， 或期待 context 自动做完整搜索。

形态 源码类型 / scope 写入者 用途
Session Session, mem:sessions /session/start 或 implicit observe 把一段工作绑定到 project/cwd/agentId，是 observation 的归属边界。
RawObservation RawObservation, mem:obs:{sid} mem::observe 保留原始事件，经过脱敏和图片抽取；可被压缩覆盖为 compressed form。
CompressedObservation CompressedObservation, mem:obs:{sid} synthetic compression 或 mem::compress 面向检索的片段：title、facts、narrative、concepts、files、importance。
Memory Memory, mem:memories mem::remember 或 consolidation 长期事实、偏好、架构、工作流。支持版本、过期时间、sourceObservationIds。
Summary / Profile / Lesson mem:summaries, mem:profiles, mem:lessons summarize、profile、reflect/lesson functions 给 context 和概览使用的高密度摘要层，不替代原始 observation。

维护要点

这个系统的能力来自“大表面面积”：hooks、MCP、REST、viewer、skills、index、graph 都在互相接线。 所以维护重点不是写一个新函数，而是保持所有入口、测试和文档同步。

Scope 是安全边界

project、cwd、agentId 决定记忆是否会跨项目或跨 agent 泄漏。显式 memory 保存时已经有 project guard。

索引是派生状态

KV 是事实来源，BM25/vector 是检索加速层。删除和升级时要考虑 index persistence， 否则删除的条目可能在重启后从旧索引“复活”。

注入默认保守

AGENTMEMORY_INJECT_CONTEXT 默认关闭部分热路径注入， 是为了避免每次工具调用都隐式消耗大量 token。

LLM 不是必需路径

observation 默认 synthetic compression，所以没有 provider key 也能检索。 summarize/consolidate/graph extract 等高级归纳才需要 LLM provider。

Skill 只是行为提示

skills 帮 agent 知道何时调用工具；真正能力在 MCP/REST/functions。 删除某个 skill 不等于删除底层 MCP prompt 或 function。

Docs 要跟着表面变

这个 fork 的 AGENTS 规则要求 MCP tool、REST endpoint、版本和 skill 数量跨 README、manifest、测试同步。
